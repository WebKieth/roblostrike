# Публикация и CI

## Опубликованная игра

- Аккаунт-владелец: `miyashiro_85`.
- Название: **RoboStrike**.
- `ROBLOX_UNIVERSE_ID`: `10771463523`.
- `ROBLOX_PLACE_ID`: `124617830529804`.
- Запуск: https://www.roblox.com/games/124617830529804/RoboStrike
- Управление: https://create.roblox.com/dashboard/creations/experiences/10771463523/overview

Игра создана и опубликована вручную в Studio. Для этой игры повторять создание
не нужно: при подключении GitHub используй ID выше. Секрет Open Cloud в проекте
не хранится; автоматическая публикация ещё требует настройки GitHub environment.

## Первое подключение аккаунта

1. Собери `./.tools/rojo build default.project.json -o build/robostrike.rbxlx`
   и открой файл в Roblox Studio под своим аккаунтом.
2. **File → Publish to Roblox As… → Create new game**. Название — Robostrike,
   владелец — твой личный аккаунт. Если игра уже создана, выбери именно её стартовый
   place. Не перезаписывай чужие или нужные существующие игры.
3. Для личного тестирования оставь игру **Private**: владелец может играть.
   Для других игроков настрой Playtest-доступ или Public в Creator Dashboard;
   Roblox может потребовать анкету контента и выполнение требований аккаунта.
4. В [Creator Dashboard](https://create.roblox.com/dashboard/creations)
   скопируй **Universe ID** игры и **Place ID** стартового места. Это разные ID.
5. В **Open Cloud → API Keys** создай ключ только для этой игры:
   разрешение **universe-places → Write**. Не используй cookie аккаунта.
   Для GitHub-hosted runners нет постоянного исходящего IP: IP-ограничения ключа
   должны допускать runner. Если нужна строгая IP-фильтрация, используй свой runner
   со статическим IP. Установи срок действия ключа и обновляй его до истечения.
6. В GitHub-репозитории создай **Settings → Environments → roblox**:
   - Secret: `ROBLOX_API_KEY` — ключ, **не отправляй его в чат и не коммить**.
   - Variables: `ROBLOX_UNIVERSE_ID`, `ROBLOX_PLACE_ID`.
   - Разреши деплой только из `main`. Для автоматического деплоя не включай
     обязательное ручное подтверждение (required reviewers).
7. Загрузи проект в GitHub с веткой `main`, включая `assets/generated/`.
   В **Actions** дождись `Test, build and publish Roblox`. Также доступен
   ручной запуск **Run workflow** с ветки `main`.

Open Cloud обновляет существующий place; создание игры и её начальная
публикация выполняются один раз в Studio. API не меняет настройки доступа игры.

## Обычный цикл

Изменения → commit → push в `main` → тесты → сборка Rojo → публикация.
Pull request только проверяется и собирается: доступа к Roblox-ключу у него нет.
Сборка `.rbxl` хранится в Actions 14 дней, в итогах публикации — версия и ссылка Play.
Устаревшие сборки пропускают публикацию, публикации не выполняются одновременно.
До подключения ID и ключа проверка/сборка работают, но шаг публикации завершится ошибкой.

**Уже работающий сервер не подхватывает новую версию.** После успешной публикации
выйди из игры и подключись к новому серверу. Если попадаешь в старый, используй
**Restart Servers / Shut Down All Servers** в управлении игрой и зайди заново.
Это прервёт сессии игроков, поэтому CI намеренно не перезапускает серверы сам.
В приватной тестовой игре без других игроков обычно достаточно выйти и зайти вновь.

## Ошибки и откат

- `401/403`: срок действия ключа, permission Write, выбранная игра, IP-ограничения.
- `404`: перепутаны Universe ID и Place ID либо у ключа нет доступа к игре.
- `409 Conflict`: конфликт сохранения, а не обязательно ошибка ключа.
  Возможная причина — Team Create или занятый сервер редактирования Roblox.
  Сначала сохрани несинхронизированные правки Studio в отдельный локальный файл,
  закрой сеансы редактирования этого place. Если включён Team Create, отключи его
  для этого place (это остановит совместное редактирование, согласуй с участниками).
  Подожди пару минут, проверь **Place → Version History** и повтори workflow
  через **Actions → Re-run failed jobs**. Если ошибка сохраняется, проверь,
  что Place ID принадлежит указанному Universe ID, и состояние сервисов Roblox.
  Не пересоздавай игру и ключ только из-за кода `409`.
- Сетевая ошибка после отправки: проверь **Place → Version History** перед повтором;
  скрипт не повторяет POST автоматически, чтобы не создавать лишние версии.
- Откат: revert нужного коммита и push в `main`, либо восстанови версию в Roblox
  Version History. Следующий push снова публикует состояние исходников Git.

Публикация не заменяет проверку в Roblox-клиенте: загрузка мешей/анимаций и их
разрешения могут отличаться от Studio. Не выдавай CI лишние разрешения на ассеты.

Документация API: https://create.roblox.com/docs/cloud/guides/usage-place-publishing
